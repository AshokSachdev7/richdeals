# SEO audit + fix — richdeals.in — 2026-09-18

Daily full-site qiaomu-seo pass. Baseline: `reports/seo-audit-2026-09-17.md`.
Scope: home, deal, store, category, blog, hubs — technical, meta, canonicals,
internal links (ALL post-body links), schema, sitemap, robots, CWV basics.

## Discovery

### Hubs (7 pages: /, /offers, /blog, /coupons, /freebies, /stores, /categories)
All 200. 1 `<h1>` each, og:image present, 0 alt-less `<img>`, explicit
`index, follow`, self-canonical. Yesterday's robots-meta fix held.
`/stores` and `/categories` render **H2:0** — thin heading structure, noted,
not fixed (they are card grids; a forced H2 would be decoration).

### Internal links (the one that actually bites)
Extracted every link out of every post body — markdown `](/...)` **and** raw
`href="/..."` — across **311 posts**: **1656 total links, 530 unique targets**.
**530/530 return HTTP 200.** Yesterday's dead-link fix held; no new rot.

### Store pages
og:image sweep over 7 stores: amazon 1, flipkart **0**, myntra 1, shopsy 1,
jiomart **0**, playstation **0**, testbook **0**. Root cause found in
`generateMetadata` (see Fixes). 4 of 7 store pages were shipping link previews
with no image.

### Category pages
Real path is `/category/<type>/<slug>` — `/category/electronics` is a genuine
HTTP 404, not a soft 404 (I misread the 404 page's metadata as the category
page's before checking status codes). Meta descriptions rendered 135-139
chars, under the 150-160 target.

### Sitemap / robots
- 9343 URLs, 2.04 MB, **0 duplicates, 0 `http://`**. Single file, not chunked
  as CLAUDE.md describes — inside the 50k/50MB protocol limits, so
  informational only, not a defect.
- Homepage canonical `https://richdeals.in` vs sitemap `https://richdeals.in/`
  — trailing-slash mismatch between the two.
- `robots.txt` ended with `Host: https://richdeals.in/`. The Yandex-only
  `Host` directive takes a bare hostname.

### 404 handling
Real HTTP 404s confirmed on `/this-page-does-not-exist-xyz123`, `/blog/nope-xyz`,
`/stores/nope-xyz`. Next emits its own `noindex` for not-found (which wins over
the layout's `index, follow`), but the page was the stock "This page could not
be found" with **no links out** — a crawl dead end.

### Slug hygiene (informational, not fixed)
1241 uppercase, 1306 over 110 chars, 1340 double-dash, 30 trailing-dash.
Uppercase case-variants correctly 404 rather than serving duplicate content,
so there is no duplicate-content exposure. Rewriting 9k live URLs to fix
cosmetics would cost more in redirect churn than it returns. Leaving them.

## Carried-over items — decisions this pass

- **W4 (fabricated FAQ claims)** — **FIXED** above. It was the one open item
  that was an actual correctness problem, not a nice-to-have.
- **W5 (nested Product/Offer inside ItemList)** — already implemented in
  `dealItemListSchema`. Nothing to do.
- **W6 (`/coupons`, `/freebies` unfiltered because the API ignores `?type=`)**
  — still open. Needs an API change plus an API deploy, which is outside a
  web-only on-page pass. Carrying.
- **W8 (Product missing `brand`/`sku`)** — **WON'T FIX as specified.** `brand`
  is deliberately omitted (the marketplace is the seller, not the
  manufacturer — the code says so). `sku` from the ASIN is feasible in
  principle but `productId` is not on the shared `DealDTO`, so it needs a DTO
  + API change, not an on-page edit. Carrying with W6.
- **Titles >60 chars / deal meta descriptions ~175 chars** — still open, both
  are template-width problems on 10k pages; worth one focused pass rather than
  a same-day nibble.
