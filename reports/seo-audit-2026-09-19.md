## What was fixed

| # | Defect | Blast radius | Fix |
|---|---|---|---|
| 1 | `/forum` title rendered doubled: `… | RichDeals | RichDeals` (73 chars) | 1 page | dropped the hardcoded suffix; the layout template supplies it |
| 2 | `dealSeoTitle()` left dangling punctuation after truncation | **665 of 10,278 LIVE deal pages (6.5%)** | one `.replace()` in the shared helper |
| 3 | 5 post-body links pointed at 308 redirects | 5 blog posts | 1 href rewritten, 4 bullet lines deleted |

### Fix 1 — `/forum` doubled title

`apps/web/src/app/layout.tsx:30` sets `template: \`%s | ${SITE_NAME}\``. `forum/page.tsx:19`
*also* hardcoded `| ${SITE_NAME}` into `metadata.title`, so Next appended it a second time.

```diff
-  title: `Deals Forum — vote, discuss and report live deals | ${SITE_NAME}`,
+  title: `Deals Forum — vote, discuss and report live deals`,
```

48 chars + ` | RichDeals` = **exactly 60**. `SITE_NAME` had only that one use left, so the
import was trimmed too or the build would warn.

**Do NOT "fix" the five files that put `| ${SITE_NAME}` into `openGraph.title`** —
`blog/[slug]`, `category/[type]/[slug]`, `compare/[slug]`, `stores/[slug]`, `[dealSlug]`.
`openGraph.title` is **not** templated by Next, so hardcoding the suffix there is correct.
`/forum` has no `openGraph` block at all; it inherits the layout defaults, which is why the
page capture still showed a correct OG title and image.

### Fix 2 — dangling punctuation on 665 deal titles

`dealSeoTitle()` (`apps/web/src/lib/site.ts:84-106`) strips trailing `[,\s]` **before**
truncating, then truncates to 48 chars and removes only the partial word. A separator left
sitting at the new end survived, producing titles like:

> `Dog Biscuits Mix Flavour, @ ₹287 (93% Off)`

The existing guard handled only the unbalanced-`(` case. One line, applied last:

```ts
// the cut above can land on a separator ("Dog Biscuits Mix Flavour," + " @ ₹287") — strip it last
name = name.replace(/[,\-–—:;/&+]+$/, "").trim();
```

**Verified by replaying the fixed helper over every LIVE row:**

```
live=10278 danglingPunct=0 over60=0 emptyName=0
```

down from 665 dangling. **No DB write was needed** — the titles are template-generated at
render time, so one helper change repairs all 665 pages at once.

## Sitemap — clean. Stop re-flagging the 10,278 vs 9,576 gap.

`/sitemap.xml` 200, 2.08 MB, **9,576 `<loc>`, 9,576 `<lastmod>` (100% coverage)**. It is a
single flat sitemap, **not** a sitemapindex.

**The DB holds 10,278 LIVE deals and the sitemap lists 9,576. That difference is
deliberate, not rot.** `dealIndexable()` (`apps/web/src/lib/site.ts:129-138`) is the gate
for both the sitemap and the robots meta; deals it rejects are intentionally excluded.
Recording this explicitly so a future audit tick does not "discover" a 702-URL hole.

**Advisory (not fixed):** `fetchAllDeals()` pages by cursor with a hard ceiling of
**200 iterations × 60 per page = 12,000 URLs**. At 10,278 LIVE the headroom is ~1,722. At
the current ingest rate that ceiling is months away, but it is a silent truncation when it
arrives — the sitemap would simply stop, with no error.

**Also still true (rot #12):** CLAUDE.md documents chunked sitemaps that prod 404s, and
`indexnow-ping.mjs` does not include `/sitemap.xml` in its auto-prepended paths.

## CWV basics — one real finding, two retractions

### Real: HTML is not edge-cacheable anywhere except `/offers`

| URL | `Cache-Control` |
|---|---|
| `/offers` | `s-maxage=31536000` |
| `/`, `/blog`, a blog post, a deal page, `/stores/amazon` | `private, no-cache, no-store, max-age=0, must-revalidate` |
| `/sitemap.xml` | `public, max-age=0, must-revalidate` |

This is the largest TTFB lever available, and it is **deliberately not applied in this
tick**. Moving those routes off `force-dynamic` onto ISR changes price freshness across
~10k deal pages — that is a rendering-mode decision with a real money-facing consequence,
not a "safe on-page fix", and the brief scopes this tick to safe fixes. Measured
`time_total` is still 0.09-0.53 s, so nothing is on fire.

The inverse is also worth flagging: **`/offers` at a one-year `s-maxage` is a stale-money
risk** on the single most price-sensitive page on the site.

Home page also loads 2 stylesheets and **61 `<script>` tags**, with preloads for
third-party `pagead2.googlesyndication.com/adsbygoogle.js` and `googletagmanager.com/gtag/js`.

### RETRACTED — "no `fetchpriority` on the LCP image"

**Wrong.** Next.js emits the React prop as camelCase `fetchPriority="high"`, and it is
present on the LCP image of both the home page and the deal page. The finding came from a
case-sensitive grep for the lowercase HTML spelling, which returns 0 on every Next site.

### RETRACTED — "0 of 65 images carry width/height → CLS risk"

**Wrong / not applicable.** Those are `next/image` in `fill` mode: they render
`data-nimg="fill"` with `position:absolute;height:100%;width:100%;…` inside a sized parent.
Absent `width`/`height` attributes there do not cause layout shift.

Both are recorded because this is precisely what the CEO-audit "verify against the source
before flagging" rule exists to catch — and both would have shipped as facts otherwise.
