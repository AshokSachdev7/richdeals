### Finding: `link.amazon` resolves — it was listed as an unhandled gap

`ingest-common.mjs` records `link.amazon` among the shortlink hosts it cannot handle. **It
resolves fine through plain `curl -sL`.** Two of this tick's four candidates came through it.

The trap worth writing down: **the path segment is not the ASIN.** `link.amazon/B02zo4wXJ` looks
like an ASIN-shaped token and is not one — the real ASIN (`B0CGRNGTM8`) appears only in the
resolved URL. Any handler that pattern-matches the shortlink path would extract garbage. Resolve
first, extract after.

## The one judgement call: `B0CGRNGTM8`

**Published, with the MRP kept and the percentage caveated in the body.**

The shape that triggered the question: a bamboo hair brush at **₹199 against a ₹1,000 MRP, -80%**.
That is the profile the implausible-MRP guard exists to catch, and the Amazon title is a bare
generic phrase ending in a full stop.

Reasoning, stated so it can be overruled:

1. **The ratio is 5.0x, not 10x.** Inflated-MRP rejects in this pipeline have been ≥10x. 5x on a
   low-ticket accessory is optimistic marketing, not a fabricated anchor.
2. **The price is the verified fact.** ₹199 is what the buybox charges, read from the logged-in
   tab. The MRP is Amazon's field, reproduced as-is — not a number we invented.
3. **The percentage is the soft claim, so it is caveated in the copy.** The description says
   outright that the 80% "reflects an optimistic MRP as much as a discount, so judge it on the
   ₹199 rather than the percentage." Publishing the discount without that line would have been the
   dishonest version.
4. **The thin title was rewritten, not reused.** `Bamboo Hair Brush With Bristles at ₹199 (80% Off)
   – Amazon` — trailing full stop dropped, the site's `at ₹X (N% Off) – Store` pattern applied.

Owner override is cheap here: `/admin/deals/10718/expire` delists it and keeps the page live with
the EXPIRED banner.

### Payload-shape correction

The first push returned `{"count":0,"results":[]}` at **HTTP 201**. The bulk endpoint takes
`{deals:[…]}`, not a bare array — `admin.controller.ts:29` does
`Array.isArray(body?.deals) ? body.deals : []`, so a bare array silently becomes zero items.

**A 201 with `count:0` is a success status on a no-op.** The only thing that caught it was reading
the count. Worth remembering: on this endpoint, HTTP status is not evidence of a write.

(The 401 before it was `ADMIN_API_KEY` vs the real `ADMIN_KEY` — my error, corrected immediately.)
