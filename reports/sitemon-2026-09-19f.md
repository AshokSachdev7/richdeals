## Rot #29 — confirmed at 89 rows, backfilled inline

The 09-19a blog tick logged one row (deal 10214) with `price` and `mrp` both present but
`discountPct` null, and set the promotion condition explicitly: *"if a second turns up, this
becomes rot #29 and the audit set needs a `discountPct IS NULL AND price IS NOT NULL AND mrp IS
NOT NULL` arm."*

Ran that query as a new audit arm this tick:

```
LIVE discountPct NULL w/ price+mrp: 89
```

Eighty-nine, not two. Every one of them was silently failing `dealIndexable`'s ≥20%-discount arm
and surviving — or not — on the ≥200-char description arm alone.

Backfilled under CEO mode with a plausibility guard, so a bad MRP is skipped rather than written:

```js
const pct = Math.round((r.mrp - r.price)/r.mrp*100);
if (r.mrp <= r.price || pct < 1 || pct > 95) { skip }
```

```
CANDIDATES 89
BACKFILLED 89   SKIPPED 0   NEWLY-INDEXABLE 4
REMAINING NULL 0
```

**Zero skipped** — every one of the 89 had a sane MRP above its price. The column was simply never
written. **Four rows crossed from "excluded from the sitemap on both arms" to indexable**; the
other 85 were already clearing the description arm and now carry a correct discount as well, which
affects the title, the Offer schema and the on-page copy.

**The class stays open.** Nothing in the ingest path guarantees `discountPct` is written when price
and MRP are known, so nothing prevents the 90th. **Recommendation: make the
`discountPct IS NULL AND price IS NOT NULL AND mrp IS NOT NULL` arm a permanent member of the
standing CEO audit set**, alongside null-price and null-image.

This is also the strongest evidence yet for open owner decision #6. The null-price/null-image arm
has been a no-op for eight consecutive ticks while 89 rows sat incomplete in a way that arm cannot
see. A row can be broken with every column the audit checks fully populated.
