## The +3 is the script, and it settles a recurring question

`apps/api/scripts/indexnow-ping.mjs`, verbatim:

```js
const paths = rawPaths
  ? args
  : ['/', '/offers', '/sitemap.xml', ...args.map((s) => `/${s.replace(/^\//, '')}`)];
```

Unless invoked with `--paths`, the script **always prepends `/`, `/offers` and `/sitemap.xml`**.
So the url count is **always slugs + 3**: 1 slug → 4 urls, 9 slugs → 12 urls, 60 slugs → 63 urls.
Every previous tick's "more urls than slugs" note has the same one-line cause; recording it here so
it stops being re-derived.

**It also means this tick's "+ sitemap" requirement is satisfied by the script itself** — no separate
sitemap submission was needed, and adding one by hand would have been a duplicate url in the same
payload (the script de-dupes with a `Set` anyway).

### On the Bing fallback

The tick asks for a Bing GET fallback **if** api.indexnow.org 422s. It returned **200**. Memory
`indexnow-bing-fallback.md` records that the 422 is a blog-ping pattern, not a deal-ping one, and
this payload was 58/60 deals. **No fallback was run.** Firing one anyway would produce a second
green line in this report that proves nothing — stating the honest single result instead.

Worth noting for the next 422: **the script has no fallback inside it.** It posts to
api.indexnow.org and prints the status, full stop. A Bing GET would have to be hand-rolled at the
call site (`https://www.bing.com/indexnow?url=<enc>&key=<key>`), or added to the script. Not changing
the script inside a submission tick.
