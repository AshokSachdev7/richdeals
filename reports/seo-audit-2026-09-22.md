## Fixes applied

**1. Four pages were emitting the wrong `og:title`.** `/about`, `/submit`, `/forum` and `/compare` each declare `title` and `description` in their `metadata` export but no `openGraph` key. Next does not merge `title` down into `openGraph` — an omitted `openGraph.title` inherits the root layout's `openGraph.title` default verbatim. All four were shipping:

```
og:title = "RichDeals — Best Deals, Coupons & Freebies in India"
```

…on four pages that are not the homepage. Every share, every social unfurl, every AI crawler reading OG instead of `<title>` saw the site name where the page name belongs. Added `openGraph: { title: "<page title>" }` to each, **without** a `| RichDeals` suffix — `openGraph.title` is not run through the `title.template`, so a suffix there would double the brand.

This does not touch the five files the 09-19 audit ruled out (`blog/[slug]`, `category/[type]/[slug]`, `compare/[slug]`, `stores/[slug]`, `[dealSlug]`). Those deliberately hand-write `| ${SITE_NAME}` into `openGraph.title` for exactly the same reason, and re-"fixing" them would strip the brand from deal shares.

**2. `/about` description was 106 chars.** Google truncates around 155-160 and a 106-char description leaves a third of the snippet unused on a page that is a primary E-E-A-T signal. Rewritten to **160** chars with real specifics (verification process, named stores, cadence) rather than padding:

> RichDeals — Best Deals, Coupons & Freebies in India. How we find, verify and publish genuine price drops from Amazon, Flipkart and 100+ Indian stores every day.

`npm run build -w @deals/web` clean. All four routes still prerender static (`/about`, `/compare`, `/submit` `○`; `/forum` `ƒ` by design — scores move constantly).

## Not fixed, and why

**Four pages with zero `<h2>`** — `/stores`, `/categories`, `/submit`, `/category/[type]/[slug]`. Real finding, third audit running, but adding headings is a visible-layout and copy decision, not a safe on-page meta fix. `/submit`'s body is a client component; the two directory hubs are card grids with no natural section breaks. Owner call on whether to restructure.

**`/offers` served with `s-maxage=31536000`** — a one-year edge cache on the most price-sensitive page on the site. Every other HTML route serves `private, no-cache, no-store, max-age=0, must-revalidate`, which is the opposite problem: no CDN caching at all on `/` and `/blog`. Both are rendering-strategy decisions with money attached (a stale `/offers` shows dead prices; caching `/` wrong shows stale deals). Not a "safe on-page fix" — carried to the owner-decision list for the third audit.

**`https://www.richdeals.in/` returns 000** — the www host still does not resolve. Fixing it is a Cloudflare DNS change, outside the repo.

**HTTP/1.1 only.** No HTTP/2 negotiated on any prod request. Cloudflare fronts the site, so this is a proxy/origin setting, not code.

**Schema** — not re-fetched. `reports/schema-audit-2026-09-19.md` (commit `e6e68f8`) validated 13 URLs across every type with **0 errors**, and its own conclusion was that re-running hours later burns the same fetches for the same answer. The ld+json block counts in the table above (1-2 per page, every page) corroborate that every type still ships structured data. Its three carried advisories stand unchanged: Product node correctly dropped on the 188 null-price EXPIRED deals (an Offer without a price is invalid schema); `sku` needs `productId` on the shared DTO (API change, out of this tick's scope); `brand` must not be synthesised from the product name.
